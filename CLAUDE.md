# Mouse Party

A macOS app for having friends over online: watching movies (and listening to music, reading PDFs and looking through SQLite databases) together, with chat and games, hosted entirely from the host's
own Mac, and leaving nothing behind when it quits. It was called TubeYap, then Mouse Party, until October 2026 (the repo was ftrain/tubeyap, then ftrain/mouseparty). There is no server: the Mac
runs MediaMTX and a small Go web server, and friends connect to it directly (or
through a Cloudflare quick tunnel). Go, with a Wails v2 window; well-known libraries over anything hand-written.

## Key files

- `app.go` - the app's state, deliberately almost buttonless: a big Play/Stop button and a big Copy-link button (a "Making link" spinner until the link is ready; the link itself is never shown) over a list you drag videos, sound files, PDFs and SQLite databases into (anything ffmpeg reads: `media.go`'s extensions, or `playable` for a lone file; a `.db` only if its header says SQLite, up to `dbMaxBytes`) and drag into order, Backspace removes the selected one; a double-click switches at any moment, and a row goes grey and is skipped while its file is gone (`watchFiles`, off the app's goroutine). A PDF up turns the playhead slider into its pages (←/→ too; past the last page moves on); songs in a row skip the countdown. A database up is like a PDF (a card on the stream) but the host makes its pages (`data.go`), has no slider, and → moves on. Adding a video (or Play) starts hosting; the copied link is Cloudflare's https one when cloudflared is there. Countdown, subtitles (text tracks offered to viewers; files dropped onto a movie) and encoding work without controls; settings live only in `~/Library/Application Support/Mouse Party/settings.json` (`config.go`). Every state change runs on one goroutine (`run`), one job at a time; after each, the window is sent a `View`. The log goes to stderr
- `frontend/` - the window: HTML and CSS, and `app.js`, built from `web/window/app.ts`. It draws the `View` and calls `window.go.main.App` methods; it keeps only a drag in progress and a held slider
- `main.go` - Wails options, the embedded files (`frontend/`, `host_web/`, `media/standby_opus.mp4`), `--selftest` (`selftest.go`)
- `stream.go` - ffmpeg commands and the `Player`: one movie, song (its cover art and tags over its sound as soft glows on a horizon, with a reflection: ffmpeg's showcqt worked out tiny, blurred, left to fade with lagfun, scaled up), countdown card or document card (while a PDF is up) to the app's MediaMTX as H264 + Opus over RTSP at 1280x720 (letterboxed), 1s keyframes, accurate seeks; positions come from `-progress` and time viewers' subtitles; burns in subtitles on request, shifting timestamps so they stay right after a seek
- `host.go` (MediaMTX and cloudflared, Start/Stop), `web.go` (the viewer site), `chat.go`, `session.go` (what viewers' pages show beside the video), `tunnel.go` (Cloudflare) + `portmap.go` + `host_web/` - hosting. MediaMTX (loopback only, except the ICE port) behind a `net/http` site that needs the session key in every path (WHEP and HLS through `httputil.ReverseProxy`, chat on gorilla/websocket); chat, subtitles and the PDF up now (served at `/doc/<token>`, page synced over the chat socket) in memory; NAT-PMP/UPnP port forwards (jackpal/go-nat-pmp, huin/goupnp; 10-minute leases, never permanent); cloudflared quick tunnel, which also turns on Cloudflare's STUN for hole punching. MediaMTX and cloudflared run under a shell watchdog so they die with the app
- `apps/` (package `apps`) + `apphost.go` + `web/viewer/apps/` - apps on the viewer page: games (Bingo, Word Grid, Tiles, Anagrams, Sketch, Blanks, Spies, Werewolf), Polls, Graffiti, Room. Nothing of them in the Mac app: any viewer opens one for everyone (the `+` by the chat box, `{"type":"app_open"}`) and any closes one (its ✕, `app_close`), up to `appsMax` at once, each a numbered `apps.Session` (`id` on every message). On the page (`host.js`) each is a window over the video that every viewer moves, sizes by its four corners and hides for themselves, tinted glass with a slider in its bar for how solid it is (`--glass`, each viewer's own, kept per app in their browser); what's inside is sized in em of a type size that follows the window's (container units, `lib.js`), so a game grows with its window, and wins throw `confetti`; on a phone, tabs (upright: in the chat's place; on its side: filling the screen); see-through ones (`Glass`: Graffiti) stay on the picture, lined up with it, under the rest. Each is a Go `Activity` holding all the state and rules, which says what each viewer sees with `View(v)` (so hands and roles stay private); `apps.Session` calls it one call at a time (so no locks), ticks it four times a second, and resends every page its view after any call that said `Room.Changed()`; frequent things (strokes) go as events (`Room.All`/`To`). An app that keeps something past the session is also a `Keeper` (`Save`/`Load`, nothing keyed by viewer IDs, which are new each session): saved to `~/Library/Application Support/Mouse Party/apps/<name>.json` a moment after it changes and when it closes, loaded when it opens (Graffiti's wall, the last poll's result). `apps/lib.go` is the shared library: `Players`, `Lobby`, `Turns`, `Vote`, `Timer`, `Msg` readers; `apps/words.go` ENABLE (`IsWord`) and the `Common` words. The script, `web/viewer/apps/<name>.ts` (built to `host_web/apps/<name>.js`, a module `host.js` imports by URL when one opens), has as its default export a `Start`, `(ctx, view) => ({view, message, ...})`, with its view, events and messages typed after its Go half (`web/viewer/types.ts` has the contract), mostly through `apps/lib.ts` (`mount`, `lobby`, `board`, `timer`, `input`, `field`, `sketch`), which it imports: one `lib.js` for them all. Messages ride each viewer's chat socket as `{"type":"app", "id"}` (rate-limited), apps opening and closing as `{"type":"apps", "op"}`. A new app: a `Kinds` entry (with a Lucide icon, added to `web/viewer/apps/icons.ts`, and a first size), its Go type, its script (its `mount` box `cover` fills its window). Names stay generic (no trademarks: Tiles, Word Grid, Sketch, Spies)
- `apps/office.go` + `web/viewer/apps/office.ts` + `host_web/office/` - documents as apps (Document, Outline, Slides, Sheet, Diagram, Drawing, Pinboard), drawn by Tiny Little Office's own editors (its `office` branch: v2 and the Pinboard, built from a pinned commit by `scripts/vendor_office.sh`; changes to them are made there, and the pin moved; its kernel `doc.js` beside them; the library's own type declarations of both in `web/office/`, which `office.ts` imports its types from). In the editors' dark theme (`setTheme`), with the page and paper as see-through as the window's slider; each editor fits its window exactly (a taller one let a focused thing scroll the bar out of sight), a Document scrolling under its bar. The host is only the order of operations the library asks for: an `edit` made against the latest version is the next one for everyone (`ops`), any other gets `retry` (ops travel as the JSON text the page wrote, passed on untouched: re-encoded, a picture's attributes would change order and the pages' texts part), and the page carries its pending ops over what it missed with the library's `cross` (following its `src/kit/share/multiparty.ts`); a page that loses its way asks `sync`; an empty document is seeded with its app's blank (a pinboard's empty table) before anyone draws on it. One document of each kind, a Keeper (text plus edits since; a page writes it down every 200). `pictures.go`: pictures for documents (`POST img`, `GET img/<id>`, kept in `~/Library/Application Support/Mouse Party/pictures`, pruned at start to what kept files name) and frames cut from the movie playing (`POST grab`, `Host.Frame`); the camera is a page command in the editor's own bar. `apps/reel.go`: Graffiti's page turns a minute after someone draws, the frame and the lines as an SVG page of the Graffiti Reel, shown as a read-only deck. `docs/a-social-office.md` is the idea
- `wasm.go` + `pandoc.go` - tools run inside the app as WebAssembly under wazero (Go: nothing to install or sign; a run sees one folder it's given, no network), compiled the first time they're wanted and kept until hosting stops, the compiled code cached in `~/Library/Caches/Mouse Party/wasm` (the program alone: nothing it read). Pandoc is its own release's `pandoc.wasm` (`scripts/fetch_pandoc.sh`, pinned and checked, into `build/pandoc/`; the app has it in `Contents/Resources/wasm`): a document brought into a Document or Slides window (its bar's file button, or dropped on it: Word, OpenOffice, PowerPoint, EPUB, HTML, LaTeX, Excel, CSV and the rest of `readFormats`) is `POST read`, one at a time, read to GitHub Markdown, which Tiny Little Office reads as it is but for pictures (made the picture store's image fences: nothing in a document is fetched), a Word rule (`--- {.rule}`, not a page break) and, for Slides, a slide at each heading; the page adds it at the end for everyone as one splice. Pandoc is GPL: releases attach its source
- `data.go` + `host_web/data.html` - a SQLite database up, looked through together, after Datasette: tables, a table's rows (sort, filters `col__op=value`, search, facets and suggested ones, foreign keys as links, 100 to a page) and read-only SQL, made by the host at `/data/<token>/...` (the file itself is never sent; `/doc/<token>` is PDFs only) and shown in a frame over the video. SQLite is modernc.org/sqlite (Go, no cgo): opened `mode=ro` with `query_only`, through its own registered driver whose authorizer allows reading and nothing else (no ATTACH, no writes, no `load_extension`, only the pragmas that describe tables), every query time- and row-limited. The page the frame shows is everyone's: it tells host.js where it is, which sends `{"type":"doc_at", token, at}` (or `back: true`), and the host keeps `at`, the trail of pages before it (Back is everyone's) and the row's `At` (it reopens there). `data.html` is read from `host_web` on every request, like the rest
- `subtitles.go` - finds a movie's subtitle tracks and the files beside it; turns text ones into cues via ffmpeg's WebVTT; language names from golang.org/x/text. `media.go`: what a file holds, read from ffmpeg's own description of it (`inspect`; there's no ffprobe), PDF page counts (pdfcpu), titles from release names
- `host_web/` - the viewer page (`viewer.html`, `host.js` built from `web/viewer/host.ts`, `host.css`, vendored `hls.min.js` and pdf.js 6.3.289's legacy build `pdf.min.mjs`/`pdf.worker.min.mjs`): YouTube-style layouts, WebRTC with HLS fallback, chat, CC menu, a PDF drawn over the video on the host's page; nothing of ours on the picture (the corners and bottom are the browser player's): CC and GUIDE live in the chat header, and full screen is the player's own, with a "Chat" subtitle track carrying chat (and subtitles) there; wipes itself when the host goes
- `scripts/build_mac_app.sh` - `wails build` (pinned, through `go run`; `wails.json`, packaging in `packaging/`) into `dist/Mouse Party.app`, with MediaMTX and cloudflared (from Homebrew) and `host_web/` in `Contents/Resources`; `BUNDLE_FFMPEG=1` for the app's own ffmpeg (`scripts/build_ffmpeg.sh`)
- `packaging/src/appicon.svg` - the icon (a house at night, a film in its window, confetti), rendered to `packaging/appicon.png` by `scripts/make_icon.sh`
- `web/` + `package.json` + `vite.config.ts` + `tsconfig.json` + `scripts/build_web.sh` - the two pages' scripts in TypeScript, set up as Tiny Little Office's are: strict `tsc --noEmit`, Prettier (`.prettierrc`) and Vite, pinned in `package-lock.json` (Node 24; dev tools only, nothing of them is shipped). `web/viewer/` builds into `host_web/` (`host.ts` to `host.js`, `apps/<name>.ts` to `apps/<name>.js`) and `web/window/` into `frontend/` (`app.ts` to `app.js`), one module a file, no bundling, no hashes, the URLs as they were; the HTML, CSS and vendored files there aren't built. What's built is checked in, so Go alone builds, vets, tests and runs the app from a clone; `scripts/build_web.sh` (`npm ci` when the lock is newer, `npm run lint`, `npm run build`) runs first in `scripts/test.sh` and `scripts/build_mac_app.sh`, and CI fails when `host_web/` or `frontend/` differ from what it builds. So change the `.ts`, never the `.js` (each says so in its first line), and commit both. What the Go side sends and takes is typed by hand (`web/viewer/types.ts`, each app's `View`, `web/window/wails.d.ts` for `app.go`'s `View` and `App` methods): a change there in Go wants its type changed too
- `scripts/test.sh` - the pages checked and built (`scripts/build_web.sh`), `go vet`, `go test` (including a play-through of three clips on free ports, one gone) and `--selftest`
- `.github/workflows/mac-app.yml` - release build on a `v*` tag: build with everything bundled, tests, self-test inside the app, zip attached to the release
- `docs/release-plan.md` - what signed macOS, Linux and Windows releases need
- `licenses/` - every bundled program, library and Go module with its licence text (README.md lists them); copied into the app as `Contents/Resources/Licenses`. Mouse Party itself is MIT (`LICENSE`); its ffmpeg is GPL, so releases attach ffmpeg's exact sources (`scripts/build_ffmpeg.sh --fetch`)

## Working on it

- The repo is public (github.com/ftrain/mouseparty): nothing private in commits. The history before it is in the private, archived ftrain/minecast.
- A new or upgraded dependency, bundled program or ffmpeg library: update its folder in `licenses/` and the tables in `licenses/README.md`.

- Never run anything that hosts on the default ports (8765, 8189) while the user's app is hosting: give a `Host` `HTTPPort: freePort(), ICEPort: freePort(), MapPorts: false, CleanLeftovers: false` (and no `Cloudflared`), as `--selftest` and `TestPlayThroughTheList` (through `App.hostSetup`) do, and a temporary `HOME` so `~/Library/Application Support/Mouse Party/settings.json` isn't touched. Host tests that skip those settings have twice stopped a live session. `wails dev` runs the real app: only with an empty `HOME`, or it starts hosting the saved list.
- The app's ffmpeg is its own: `scripts/build_ffmpeg.sh` builds it static from pinned sources (x264, Opus, FreeType, FriBidi, HarfBuzz, libass, FFmpeg) into `build/ffmpeg/bin`, cut down to every decoder and container but only the encoders (libx264, libopus, png, webvtt), muxers and filters the app uses. A new filter or encoder in `stream.go` needs adding there too, or it fails only when streaming. There's no ffprobe: `inspect` reads ffmpeg's own description of a file. Homebrew's ffmpeg has no `drawtext`, so cards fail with it; `scripts/test.sh` uses the built one.
- The window can be checked without the app: headless Chrome on `frontend/` with stand-in `window.go`/`window.runtime` objects.
- The running app reads `host_web/` from `/Applications/Mouse Party.app/Contents/Resources/host_web/` on every page load (the copy built in is the fallback), so viewer-page fixes can go live by copying files there (after `npm run build`); Go changes need a rebuild, installed once the app has quit.
