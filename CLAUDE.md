# Mouse Party

A desktop app for macOS, Linux (Fedora: an RPM and an AppImage) and Windows (a per-user installer), for having friends over online: watching movies (and listening to music, reading PDFs and looking through SQLite databases) together, with chat and games, hosted entirely from the host's
own computer, and leaving nothing behind when it quits. It was called TubeYap until October 2026, then for a few days Open House Party (the repo was ftrain/tubeyap, then ftrain/openhouseparty; it's ftrain/mouseparty now). There is no server: the host's computer
runs MediaMTX and a small Go web server, and friends connect to it directly (or
through a Cloudflare quick tunnel). Go, with a Wails v2 window; well-known libraries over anything hand-written.

## Key files

- `app.go` - the app's state, deliberately almost buttonless: a big Play/Stop button and a big Copy-link button (a "Making link" spinner until the link is ready; the link itself is never shown) over a list you drag videos, sound files, PDFs, SQLite databases, other documents and zips into (anything ffmpeg reads: `media.go`'s extensions, or `playable` for a lone file; a document pandoc reads is a `text` row, read by pandoc when it's up (`session.go` `readText`) and laid out as pages on viewers' pages by Tiny Little Office's view of it (write, deck or sheet: `appOf(app).view`, drawn with `pageSvg`; a write one on Letter for everyone, its column then cut into screen-shaped pages between lines, `screenPages` in `host.ts`, so its type is twice a paper page's), served as its text at `/doc/<token>` once read; a zip is unpacked beside it as the Finder does (`zip.go`: its one folder, or a folder of its name, "name 2" if taken; nothing outside it, no links, no hidden files, limits on count and size) and its files taken as a folder's; a `.db` only if its header says SQLite, up to `dbMaxBytes`) and drag into order, Backspace removes the selected one, Party > Clear Played Files (⌘R, `clearPlayed`) every row above the position, Party > Erase All Data… (`App.EraseAll`, the `erase` sheet; no shortcut) everything kept (`erasable`: the data folder, the cache, Open House Party's folders on the Mac; `a.erased` stops every save, and `afterErase` deletes the window's defaults and WebKit's storage once the app has quit, then opens it again), Edit > Undo putting them back (`mac.go`), and an icon column says what each row is (`Row.Icon`: video, audio, pdf, text, db, or download); Party > Add Download Link… (`download.go`: the `ask` event's `link` sheet, `App.AddURL`) adds a row by its URL, as a file service hands one out: the file is fetched in Go (the app's ffmpeg speaks no https) into `~/Library/Caches/Mouse Party/downloads/<hash of the link>/`, the row with its download arrow and bytes, written straight to its place and playable as soon as ffmpeg reads it with a length (`download.ready`: `off` lifts, the slider reaching only as far as the bytes do, `downloadedSeconds`), ffmpeg's end of the partial file taken by `finished` as running out, `App.resume` set and `resumeDownloading` playing on from there once there's more (resumed with Range after a quit; a failed one tried again at the next start, or on a double-click; a site that wants a login gets one, HTTP Basic auth: `logins.go`, the sheet's username and password or one written into the link, taken out of it, kept per site, the registered domain by `publicsuffix`, in the party file's `settings` under `logins` (never the `config` that Edit as Text shows) when the sheet's "Save this login" is on, else only until the app quits (`App.tempLogins`), and sent by `withLogin` only to that site, only over https or to this Mac, redirects within the site too; a link already in the list added again with one is tried again with it), then looked at as a dropped file is (`fileItem`) and played from the cache; removing the row deletes its folder, and `syncDownloads` at start deletes folders no row names; the cache keeps at most `cache_gb` (`Config.CacheGB`, 20): a link bigger is refused and `trimCache` deletes the downloads played longest ago (`touchDownload` on play) until the rest fits, their rows going too (`removeItems`), as Party > Clear Download Cache… (`App.ClearCache`, the `clear` sheet) does to all but the one playing; the cache holds the list's downloads and nothing else (`pruneCache` after any row goes; an earlier version's greyed `Cleared` rows are taken out at start); files dropped on the Dock icon arrive one by one through Wails's `OnFileOpen` (`openFile`, gathered for a moment and added as one drop; `packaging/darwin/Info.plist` declares any file or folder viewable, ranked Alternate so the app is never anything's default); a video stopped partway (Stop, a quit, another row double-clicked) keeps its place (`Item.Paused`, `keepPlace`: not in its first 15 seconds or last minute) and plays on from 5 seconds before it, its row saying "42:10 of 1:45:00", forgotten once played through; a video whose sound and picture don't line up has its sound moved earlier or later (`Item.Sound`, ±3 s: Settings > Streaming's Sound sync slider, `App.SetSound`, for the movie up now, which starts again where it is; `soundShift`: `adelay`, or `atrim` for earlier), the same for every viewer; a double-click switches at any moment, and a row goes grey and is skipped while its file is gone (`watchFiles`, off the app's goroutine). A PDF up, or another document once a viewer's page has laid it out (`doc_pages`), turns the playhead slider into its pages (←/→ too; past the last page moves on): the page everyone is on. Every viewer has the same slider and keys, and turns it for everyone (`pace.go`): a slider resting on a page turns everyone's there (`doc_page`, through the app's `showPage`), chat saying who; or a viewer reads on their own ("read on my own"), their slider moving only their page, chat saying where they rest (`doc_read`) and when they're back, a "go there" link taking anyone there on their own; "notes" opens Stickies, which says in chat where each note goes (`Movie.Say`). The pace (a page every so many seconds, or off) is everyone's, anyone making it faster or slower (`doc_pace`), chat saying who; at the last page it stops. Songs in a row skip the countdown. A database up is like a PDF (a card on the stream) but its pages are Datasette's (`datasette.go`), has no slider, and → moves on. Adding a video (or Play) starts hosting; the copied link is Cloudflare's https one when cloudflared is there. Countdown, subtitles (text tracks offered to viewers; files dropped onto a movie) and encoding work without controls; settings live only in the party file (`config.go`, `store.go`). Every state change runs on one goroutine (`run`), one job at a time; after each, the window is sent a `View`. The log goes to stderr
- `frontend/` - the window: HTML and CSS, and `app.js` (a module) and `party.js`, built from `web/window/`. It draws the `View` and calls `window.go.main.App` methods; it keeps only a drag in progress and a held slider. `party.ts` is the party file's sheets over it: the passcode while it's locked (`View.locked`), and what the Party menu asks for (the `ask` event: Add Download Link, with its login and "Save this login for <site>", filled in from `App.LoginFor` as a link is pasted; Clear Download Cache, Use Encryption, Change Passcode, Stop Using Encryption, Edit as Text, `prefs`, and Help's `keys`, `welcome` (also at the first load with an empty list, `App.Welcome`) and `log`), and the `edit` event (Edit > Undo/Redo: a focused field's typing, else `App.UndoRemove`/`RedoRemove`); `app.ts` also has ↑/↓ and Return for the list, and ARIA roles and labels; `prefs.ts` is the Settings window (Mouse Party > Settings…, ⌘,; `prefs.go`: `Prefs`, `SetPrefs` keeping each change as it's made, a bandwidth one of `bitrates` (another, as `loadConfig` reads it, the nearest: High, 2500k, the default), `SaveAccount`/`RemoveAccount`), tabs as a Mac app's Settings (General, Streaming, Network, Downloads, Accounts, Security), a sheet opened from it (`askFrom`) going back to it; while one is up the window's own keys (Backspace removes a row) leave it alone
- `mac.go` + `native_darwin.go` - what makes it a Mac app around the window: the menu bar built whole (Wails v2's app menu role can't hold Settings…, so the app menu is our own: About, Check for Updates…/Restart to Update, Settings…, Hide, Hide Others, Show All, Quit, through `runtime.Quit` so `beforeClose` still asks; Edit with Undo/Redo as the list's (`App.undo`/`redo`: `takeOut` records rows removed by Backspace and Clear Played Files and where they were, their downloads kept in the cache, `pruneCache` sparing them, until `forget`: another removal, room made, the cache cleared, Edit as Text) and Cut/Copy/Paste/Select All sent along AppKit's responder chain (`nativeSend`); Party; Window; Help: the README, Keyboard Shortcuts, Welcome, Show Log, Release Notes). Cgo to AppKit for the standard About panel (the version from Info.plist), Hide Others, the Dock badge (downloads' percent, `badge` after each view), the window's frame kept in the app's defaults (`setFrameAutosaveName`, at DOM ready), and whether the app is in front (`NSRunningApplication`, any thread: never `dispatch_sync` to the main thread, which may be waiting on the app's goroutine). Notifications (Wails's, asked for the first time one's wanted, `Config.Notify`) only while it's behind: a friend's first name in chat (`Host.Arrived`), a download done. The log (`App.log`) is kept in memory too, the last `logMax` lines, for Show Log. Off macOS the shell is `menu_other.go` + `native_linux.go` / `native_windows.go` + `options_*.go` (`menu_darwin.go` is the Mac's menu, as it was): the menus are built once and never changed (Wails 2.17.1 on Linux crashes on a menu set again, so `setMenu` does nothing there, and no item carries state: Undo, Encryption…, Check for Updates…); Linux has File, Edit (Preferences at its end), Party and Help, Windows &File (Settings…, Exit), &Edit, &Party and &Help with each shortcut after a tab. Cut, Copy, Paste and Select All carry no accelerators off macOS (WebKitGTK and WebView2 handle those keys in fields themselves; clicked, they go through the `edit` event), and outside fields `app.ts` takes Ctrl+Z, Shift+Ctrl+Z and Ctrl+Y. About is a sheet (`App.About`); the badge is the window title ("Mouse Party – 42%"); "in front" is the page's focus on Linux (`App.Focused`) and the foreground window's process on Windows; the frame is `dataDir()/window.json` (Linux: the size; Windows: the placement, the window starting hidden until DomReady). On Linux the list's start (`begin`) waits for DomReady, which comes after Wails's single-instance check, and the link leaves the clipboard in `beforeClose`, before GTK's loop ends; `beforeClose` takes the Linux and Windows dialogs' "Yes", and a canceled quit cancels Restart to Update; files given as arguments (Open With, a second launch) go to `openFile`; the window is taller there, to hold its menu bar; a dragged link or text does nothing. Check for Updates… is grayed out on the Mac while the party is locked and does nothing elsewhere while it is; the sandbox's notes (`sandboxLog`) go to the log on every OS; on Windows a sign-out, restart or shutdown (`WM_ENDSESSION`, `quitWithSession`) saves and stops as a quit does, for at most 4 s, without putting an update in, reopening or erasing. `App.log` goes to stderr only on a terminal or with `MOUSEPARTY_LOG=stderr` (GNOME keeps an app's stderr in the journal)
- `main.go` - Wails options, the embedded files (`frontend/`, `host_web/`, `media/standby_opus.mp4`), `--selftest` (`selftest.go`)
- `stream.go` - ffmpeg commands and the `Player`: one movie, song (its cover art and tags over its sound as soft glows on a horizon, with a reflection: ffmpeg's showcqt worked out tiny, blurred, left to fade with lagfun, scaled up), countdown card or document card (while a PDF is up) to the app's MediaMTX as H264 + Opus over RTSP at 1280x720 (letterboxed), 1s keyframes, x264's `zerolatency` (MediaMTX times a new publisher from when it connects, so a lookahead's held-back second left viewers' browsers a second behind after each hand-off, the sound drifting late as they caught up), accurate seeks; positions come from `-progress` and time viewers' subtitles; burns in subtitles on request, shifting timestamps so they stay right after a seek
- `host.go` (MediaMTX and cloudflared, Start/Stop), `web.go` (the viewer site), `chat.go` (in memory only, never written: `TestChatIsNeverKept`), `session.go` (what viewers' pages show beside the video), `tunnel.go` (Cloudflare) + `portmap.go` + `host_web/` - hosting. MediaMTX (loopback only, except the ICE port) behind a `net/http` site that needs the session key in every path (WHEP and HLS through `httputil.ReverseProxy`, chat on gorilla/websocket); chat, subtitles and the PDF up now (served at `/doc/<token>`, page synced over the chat socket) in memory; NAT-PMP/UPnP port forwards (jackpal/go-nat-pmp, huin/goupnp; 10-minute leases, never permanent); cloudflared quick tunnel, which also turns on Cloudflare's STUN for hole punching. MediaMTX and cloudflared run under a shell watchdog so they die with the app (on Windows in kill-on-close jobs instead); each session holds `<session>/lock` for its whole life, and the sweep of leftover `mouseparty-host-*` folders at start (`killLeftovers`) takes a folder only once it has that lock, so a session it can't see (another PID namespace) keeps its folder; on Linux a leftover tool is one whose process group's leader, its watchdog, is gone, whoever adopted it; MediaMTX gone as it starts (a loopback port taken before it listened) is started again on fresh ports (`startMediaMTX`), one that dies while hosting on the same ones
- `host_web/icon.png` - the icon for the viewer page (256 px, `sips -Z 256 packaging/appicon.png`): its favicon, the logo in the guide's head (a link to the website), and laid at the top of each countdown card (`stream.go` `iconCard`, a third ffmpeg input, written to a temporary file by `iconFile`). The page is labelled for screen readers: chat is a `role="log"` live region, the status and who's here `role="status"`, the ended or full note `role="alert"`, every symbol-only button has an `aria-label`, and each app window is a labelled group; a PDF or document drawn on a canvas, and the drawing apps, are not readable by one
- `archive.go` - an Internet Archive page link (`archive.org/details/<item>`) given to Add Download Link is turned into its video's download link before anything else looks at it (`App.AddURL`): the item's files from the Archive's metadata API, of which `archivePick` takes each video once (its h.264 MP4 copy, else the biggest of the files named alike), in name order, a row each (up to `archiveMost`), or with no video its sound files; a page link that names a file is that file. Downloads come down three at a time, the rest in turn (`downloadSlots`, `fetchInTurn`)
- `chat.go`'s `Chat.max` (`Host.MaxViewers`, the party file's `max_viewers`, 10; Settings > Network's Guests; 0 for no limit) - how many can watch at once, counted as chat sockets: with that many, the page is `fullPage` (503), a socket is sent `{"type":"full"}` and closed (the page says sorry and doesn't try again: `endSession(true)`), and a WebRTC handshake for the movie is refused when MediaMTX already sends to that many (`videoFull`). It's read when hosting starts
- `sandbox.go` + `site.go` - what a stranger's bytes can reach runs in a macOS sandbox (Seatbelt, through `/usr/bin/sandbox-exec`; a profile written for each run, `box`: deny everything, `system.sb`, then what's named, paths as `-D` parameters), none able to start a program or see the home folder. The viewer site is a second copy of the app, `--site` (`siteMain`; `TestMain` does the same for a host under test), started by `Host.startSite` when `Host.Sandbox` (the app and `--selftest` set it; a `Host` made bare in a test holds its session itself, as before): it reads the app's `Resources`, pandoc and the Python, writes its own folder in the session's and the wasm cache, answers on the site's port (taken by the app, which says if it can't be, and inherited) and of this Mac's ports reaches only MediaMTX's API, HLS and WebRTC. Chat, the apps, pandoc and Datasette all run there (`Host.session`, the same code), so the app's `Host` then has no `chat` or `apps`: every setter (`SetDocument`, `SetPosition`...) both keeps what it was given and `tell`s the site (`SiteCalls.Tell`, Go's net/rpc over a socket pair; a document's file is opened by the app and handed over open on a third socket, `document.file`, and of its path only the name goes), and a site that dies is started again and told it all again (`siteGone`, `launchSite`). What the site asks of the app is `MacCalls`, each checked as a stranger's would be: what apps and pictures keep in the party file (`siteSide` is the site's `apps.Shelf` and `pictureKeeper`; only an app's name or `reel`, sizes capped), a frame of the movie (ffmpeg stays with the app), and what viewers did that the window shows (`SiteEvent`: a page turned, a name, a log line). The site won't start if it can read a file left outside its box (`SiteSetup.Canary`). MediaMTX and cloudflared get theirs in `Host.boxFor` (MediaMTX: the session's folder, loopback, the ICE port, UDP out; cloudflared: no files, Cloudflare's ports and the site's), ffmpeg in `ffmpegCmd`, which every ffmpeg run goes through: it reads its `-i` files and reads and writes the temporary files it's handed (`own`), and reaches only the `rtsp://127.0.0.1:<port>` among its arguments, so a path inside a filter must be an input or one of `own` (a burned-in subtitle file is always a temporary copy, `offsetSRT`). `no_sandbox` in the party file (Edit as Text) turns it all off. `TestBoxesKeepTheMacOut` tries each box with the test binary as the program (`--probe`, `probe_test.go`, `probe_linux_test.go`): reading, listing, writing, file times, starting a program, ports, and on Linux the system calls the seccomp filter refuses. On Linux and Windows the box is the app's own launcher (`--box <spec> -- <program> <args>`, `box_other.go` builds the spec from the same `read`/`write`/`reachLocal`/`serveTCP`... calls that `sandbox_darwin.go` turns into Seatbelt rules): on Linux (`box_linux.go`) it locks its thread, takes away core dumps, closes every inherited descriptor but the ones handed over (the site's 3-6), keeps a small environment, applies Landlock (files; TCP bind and connect by port, from ABI 4; signal and abstract-socket scopes, from ABI 6; newer rights when the kernel takes them) and a seccomp filter (only IPv4/IPv6 sockets, TCP alone unless the box has UDP, so Go's default MPTCP listeners fall back to TCP, which Landlock holds; netlink only for MediaMTX; no io_uring, namespaces or clone3; changing a file's mode, owner, times or extended attributes by its path refused, as Seatbelt does outside a box's write rules, and no keyrings or System V IPC), then execs; execute rights cover only the program and its ELF interpreter, and the site also bans `execve` for all its threads at start (`site_linux.go`, seccomp with TSYNC). Landlock can't hold addresses (a port is allowed on any address), nor UDP before the kernel has UDP rights; `sandboxLimits` says once when the kernel is too old to box ports at all (before ABI 4). After a `dnf upgrade` during a party, new helpers start from the new program file until Mouse Party is opened again. On Windows (`box_windows.go`) the launcher creates the program straight into a job of its own (kill-on-close, one process, die on an unhandled exception, the UI limits) with a restricted low-integrity token (Administrators deny-only), labels Low only the folders it may write (inside the temporary folder or the wasm cache, never through a link), passes on only its standard handles and the handed ones and a small environment (as on Linux: what Windows programs need, and what the box names), and watches the app's process: it keeps a program from writing the user's files, starting programs, touching other windows or the clipboard and outliving the app, not from reading files or the network (`sandboxLimits` says so). The site link per OS: `site_unix.go` (socket pairs, `SCM_RIGHTS`, the inherited listener), `site_windows.go` (four anonymous pipes named in `MOUSEPARTY_SITE`, the site binding its own port, which the app checks is free first, and documents by `DuplicateHandle` into the site's process, which `Site.Pid` names and the app checks is its launcher's child); the canary is "can't read it" on macOS and Linux and "can't write it" on Windows, where it's labelled Medium. On Linux and Windows MediaMTX writes only a folder of its own in the session's (`<session>/mediamtx`), reading its config and the stand-by video
- `apps/` (package `apps`) + `apphost.go` + `web/viewer/apps/` - apps on the viewer page: games (Bingo, Word Grid, Tiles, Anagrams, Sketch, Blanks, Spies, Werewolf), Polls, Graffiti, Stickies, Room, Call. Nothing of them in the Mac app: any viewer opens one for everyone (the `+` by the chat box, `{"type":"app_open"}`) and any closes one (its ✕, `app_close`), up to `appsMax` at once, each a numbered `apps.Session` (`id` on every message). On the page (`host.js`) each is a window over the video that every viewer moves, sizes by its four corners and hides for themselves, tinted glass with a slider in its bar for how solid it is (`--glass`, 0.02 to 1: at its least the barest glimmer; each viewer's own, kept per app in their browser; a window with things on a ground fades in two halves, `--glass-ground` over the slider's first half and `--glass-things` over the second); what's inside is sized in em of a type size that follows the window's (container units, `lib.js`), so a game grows with its window, and wins throw `confetti`; on a phone, tabs (upright: in the chat's place; on its side: filling the screen); see-through ones (`Glass`: Graffiti, Stickies) stay on the picture, lined up with it, under the rest; a `bare` one (Stickies) has no window at all, its script drawing its own bar and close (`ctx.close`). Each is a Go `Activity` holding all the state and rules, which says what each viewer sees with `View(v)` (so hands and roles stay private); `apps.Session` calls it one call at a time (so no locks), ticks it four times a second, and resends every page its view after any call that said `Room.Changed()`; frequent things (strokes) go as events (`Room.All`/`To`). Graffiti and Sketch draw on a `wall` (`graffiti.go`): each line has an ID the host gives it (its pieces share it, by the page's `n`), the eraser (`erase`) takes every line its path touches, `undo` the sender's own last line, `clear` all (Graffiti's asks twice on the page and says who in chat). A game's `Lobby.Reopen(r)` drops whoever left mid-game and doesn't count down: the next begins on Start, or a join. An app that keeps something past the session is also a `Keeper` (`Save`/`Load`, nothing keyed by viewer IDs, which are new each session): saved on the host's `apps.Shelf` (the party file's `kept` table, by the app's name) a moment after it changes and when it closes, loaded when it opens (Graffiti's wall, the last poll's result). `apps/lib.go` is the shared library: `Players`, `Lobby`, `Turns`, `Vote`, `Timer`, `Msg` readers; `apps/words.go` ENABLE (`IsWord`) and the `Common` words. The script, `web/viewer/apps/<name>.ts` (built to `host_web/apps/<name>.js`, a module `host.js` imports by URL when one opens), has as its default export a `Start`, `(ctx, view) => ({view, message, ...})`, with its view, events and messages typed after its Go half (`web/viewer/types.ts` has the contract), mostly through `apps/lib.ts` (`mount`, `lobby`, `board`, `timer`, `input`, `field`, `sketch`), which it imports: one `lib.js` for them all. Messages ride each viewer's chat socket as `{"type":"app", "id"}` (rate-limited), apps opening and closing as `{"type":"apps", "op"}`. A new app: a `Kinds` entry (with a Lucide icon, added to `web/viewer/apps/icons.ts`, and a first size), its Go type, its script (its `mount` box `cover` fills its window). Names stay generic (no trademarks: Tiles, Word Grid, Sketch, Spies)
- `apps/stickies.go` + `web/viewer/apps/stickies.ts` - Stickies: notes on what's playing, signed with the writer's chat name, in a colour they pick as they go, anchored to a moment (seconds in) of a movie or a song or to a page of a document (`Movie.Playing`: the host's `SetPlaying`, a hash of the file's path as its key). Kept by that key (a Keeper), they show again whenever it plays: a moment's for 8 seconds from it, a page's while that page is up on the viewer's own screen (`ctx.now()`). Only a note's writer moves, recolours or takes it off. Chat says when a note goes on or comes off, and where (a page's line links there)
- `apps/call.go` + `web/viewer/apps/call.ts` - Call: voices, talking while watching. Joining sends the page's microphone to MediaMTX over WebRTC (WHIP, `call/send/<secret>`) and hears each other voice in the call as its own WHEP connection (`call/hear/<voice>`), through `web.go`'s `webrtcProxy`, on the movie's ICE port and STUN; MediaMTX's `call-<voice>` paths, a publisher each, never overridden. The secret is only in its caller's view; the public voice is a hash of it (`apps.CallName`), so the proxy needs nothing from the app to know who may send where. Every voice goes from the host's Mac to everyone else in the call (`callMax`). Browsers lend the microphone only to a secure page: the Cloudflare https link, not the plain http one, which the app says
- `apps/office.go` + `web/viewer/apps/office.ts` + `host_web/office/` - documents as apps (Document, Outline, Slides, Sheet, Diagram, Drawing, Pinboard), drawn by Tiny Little Office's own editors (its `office` branch: v2 and the Pinboard, built from a pinned commit by `scripts/vendor_office.sh`; changes to them are made there, and the pin moved; its kernel `doc.js` beside them; the library's own type declarations of both in `web/office/`, which `office.ts` imports its types from). In the editors' dark theme (`setTheme`), with the page and paper as see-through as the window's slider (the Pinboard in two halves: its ground, then its things); each editor fits its window exactly (a taller one let a focused thing scroll the bar out of sight), a Document scrolling under its bar. A window too narrow for its editor's bar in one row (measured from its buttons) folds the bar into a menu button (☰), the bar shown wrapped under it while it's open. The host is only the order of operations the library asks for: an `edit` made against the latest version is the next one for everyone (`ops`), any other gets `retry` (ops travel as the JSON text the page wrote, passed on untouched: re-encoded, a picture's attributes would change order and the pages' texts part), and the page carries its pending ops over what it missed with the library's `cross` (following its `src/kit/share/multiparty.ts`); a page that loses its way asks `sync`; an empty document is seeded with its app's blank (a pinboard's empty table) before anyone draws on it (two pages seeding at once: the second is sent the `state`, and a page that was still loading the library starts from the newest view). One document of each kind, a Keeper (text plus edits since; a page writes it down every 200). `pictures.go`: pictures for documents (`POST img`, `GET img/<id>`, kept in the party file, pruned at start to what's kept names) and frames cut from the movie playing (`POST grab`, `Host.Frame`); the camera is a page command in the editor's own bar. `apps/reel.go`: Graffiti's page turns a minute after someone draws, the frame and the lines as an SVG page of the Graffiti Reel, shown as a read-only deck. `docs/a-social-office.md` is the idea
- `store.go` + `party.go` - the party file, `~/Library/Application Support/Mouse Party/party.sqlite`: everything kept, in one SQLite file (ncruces/go-sqlite3: SQLite as WebAssembly translated to Go, no cgo; ``selftest.go` makes its database with it too; Datasette's SQLite is its own, in the WebAssembly Python). Tables `settings` (the `Config` as one JSON value, `config`), `kept` (what apps and the reel keep: `apps.Shelf`), `pictures`; never the media files, nor anything of a session (the link, who came, chat). Journal mode DELETE and temp in memory, so it's one file at rest. The Party menu's Use Encryption… seals it with a passcode (the adiantum VFS: every page encrypted, the key from the passcode by Argon2id; private, not tamper-proof): `VACUUM INTO` a sealed copy beside it, put over it. Sealed, the app starts locked (`View.Locked`): the window asks for the passcode (`App.Unlock`; each wrong one waits longer), nothing hosts and nothing can be added until it opens; Start Over sets a locked file aside, never deleting it. The first party made takes in Open House Party's files (`importOld`) and renames their folder (on the Mac only). `docs/one-file.md` is the design. ## Working on it

- The repo is public (github.com/ftrain/mouseparty): nothing private in commits. The history before it is in the private, archived ftrain/minecast.
- A new or upgraded dependency, bundled program or ffmpeg library: update its folder in `licenses/` and the tables in `licenses/README.md`.

- The user often has the app running from `dist/Mouse Party.app` while working: `scripts/build_mac_app.sh` replaces that bundle, so build with `DIST=<somewhere else>` unless asked to replace it (the Linux and Windows scripts take `DIST` too).
- A new thing a boxed program needs (a file, a port, a system service) is a rule in its box (`sandbox.go`, `site.go`'s `siteBox`, `host.go`'s `boxFor`), or it fails only when it runs boxed: on macOS a denial shows in `log show --predicate 'eventMessage CONTAINS "deny"'`; on Linux it is only an EACCES or EPERM where the program asked (no log), and on Windows an access-denied. A stand-in for a tool that's a shell script can't run in a box (the box lets it start no shell): such a test calls `unboxed(t)`.
- Never run anything that hosts on the default ports (8765, 8189) while the user's app is hosting: give a `Host` `HTTPPort: freePort(), ICEPort: freePort(), MapPorts: false, CleanLeftovers: false` (and no `Cloudflared`), as `--selftest` and `TestPlayThroughTheList` (through `App.hostSetup`) do, and a temporary home so the real party file isn't touched: in tests `tempHome(t)` (HOME, the XDG folders, APPDATA, LOCALAPPDATA, USERPROFILE), `testApp(t)` for an App (free ports, no router, no tunnel; `hostingInTests` makes `hostStart` panic for an App without `hostSetup`), and `TestMain` gives the whole run one and won't run if `dataDir()` or the caches would land outside `os.TempDir()`. Stand-ins for tools are the test binary (`fake_test.go`, `MOUSEPARTY_FAKE_TOOL`), not shell scripts, wherever a test runs on Windows. Host tests that skip those settings have twice stopped a live session. `wails dev` runs the real app: only with an empty `HOME`, or it starts hosting the saved list.
- The app's ffmpeg is its own: `scripts/build_ffmpeg.sh` builds it static from pinned sources (x264, Opus, FreeType, FriBidi, HarfBuzz, libass, FFmpeg; on Linux also fontconfig and expat, linking only glibc, 2.38 or later) into `build/ffmpeg/bin` (`TARGET=windows-amd64`: `build/ffmpeg-windows-amd64`, cross-built with mingw-w64), cut down to every decoder and container but only the encoders (libx264, libopus, png, webvtt; pcm_s16le, for `TestSoundShift` to hear where a sound falls), muxers and filters the app uses. A new filter or encoder in `stream.go` needs adding there too, or it fails only when streaming. There's no ffprobe: `inspect` reads ffmpeg's own description of a file. Homebrew's ffmpeg has no `drawtext`, so cards fail with it; `scripts/test.sh` uses the built one.
- The window can be checked without the app: headless Chrome on `frontend/` with stand-in `window.go`/`window.runtime` objects.
- The running app reads `host_web/` from `/Applications/Mouse Party.app/Contents/Resources/host_web/` (on Linux and Windows the installed `resources/host_web/`) on every page load (the copy built in is the fallback), so viewer-page fixes can go live by copying files there (after `npm run build`); Go changes need a rebuild, installed once the app has quit.
